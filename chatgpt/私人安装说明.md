# 私人安装与使用

本包用于私人交付，可由作者托管在自己的 Private GitHub 仓库；不会公开发布到插件市场或外部服务。代码引擎没有网络客户端、外部 API 或遥测。私有 GitHub 下载方式见 README，需先登录有权限的账户。

## 创建私人自定义 GPT

1. 在你的 ChatGPT 账号打开创建 GPT（是否可用取决于账号功能）。
2. 名称可用“我的 Story Writer”；粘贴 `GPT指令.md` 到 Instructions。
3. 启用代码解释器/数据分析。上传 `知识库.md` 和 `plugins/story-writer/references` 下三份 Markdown 到 Knowledge。
4. 不添加 Actions。关闭不需要的联网能力，减少误传素材的路径。
5. 保存时选 **仅我可见 / Only me**，不要选“任何知道链接的人”或公开发布。具体 UI 名称以当前账号为准。
6. 新对话上传本工具包 ZIP，让 GPT 检查文件并调用实际引擎。只有收到真实运行结果后才算工具已可执行。

以上步骤由你在账号中完成；本次未替你创建、安装或设置 GPT 可见性。自定义 GPT 的 Knowledge 是说明资料，不保证可直接执行其中的 Python，所以工具包需要会话上传。

## 不创建 GPT 的用法

在普通 ChatGPT 数据分析对话粘贴 GPT 指令、上传 ZIP，然后发：

> 请按 Story Writer 流程私人管理我的故事。先解压工具包并核验引擎，作品名是……，形式是……。不要公开、不要连接外部服务。先建立作品契约和待确认方案。

无数据分析功能时，可继续采用文字版流程，无法保证脚本执行与文件持久化。不要把文字承诺当“已保存书仓”。

## 下次继续

结束前说：

> 核验书仓，导出最新完整备份 ZIP 给我下载，另外导出已定稿正文。

下次上传最新书仓和工具包，发：

> 恢复这个书仓到新目录，核验来源和定稿事务，从实际文件判断下一步。不要根据记忆重建剧情。

工具包备份与书仓备份不同：前者是引擎/说明，后者是你的创作数据。书仓、作者看板和审读包含机密，私人存放；不要分享给读者或上传公开平台。
