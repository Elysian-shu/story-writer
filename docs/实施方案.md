# Story Writer 通用写作管理实施方案

## 目标与当前范围

给 ChatGPT 一个可检查、可暂停、可恢复的故事工作流程，让作者把精力放在内容决策。以私人自定义 GPT + 无依赖引擎 + 本地书仓为第一版，不增加外部服务或公开发布。用户最新要求是通用故事管理；原先《献生》专用版本未继续填充剧情，四案资料尚未取得。

适配长篇、短篇、剧本、漫画脚本、儿童故事、实验叙事和纪实叙事。通用性来自数据模型与可配置审读，不代表已在所有题材、全部语言或所有 ChatGPT 版本上验收。

## 一、产品交互

作者只需说“建书、导入、规划、继续、审读、修订、查看、导出”。GPT 把自然语言变成文件与 CLI 调用。每次实际结果先呈现，再在必要的事实取舍、核心方向或定稿上依据作者授权继续。常规备料、起草、检查、诊断与备份不反复请求许可。

结果以三个信息组成：本次成果、真实问题、下一步。技术路径用于下载/恢复，JSON 与哈希留在文件，不混入正文。

## 二、分层与真源

| 层 | 工件 | 权限/语义 |
|---|---|---|
| 原始资料 | 原件、UTF-8 文本、来源元数据 | 保留作者输入；只作为证据，未自动确认 |
| 候选 | 提案、草稿、修改方案 | 可探索，可拒绝，不能冒充正史 |
| 作者规划 | 契约说明、单元卡、章合同 | 区分可读笔记与实际运行约束 |
| 正史 | 已确认来源事务、定稿正文事务 | 只追加，修订留历史 |
| 读视图 | 查询、看板、正文合集 | 从正史生成，不反向更新事实 |

书仓树：

```text
作品目录/
├── .故事/项目.json、暂存/
├── 作品契约.md
├── 原始资料/S-编号.txt、.original、.json
├── 世界书/
├── 故事单元/单元01/单元卡.md
├── 工作区/候选、章合同、备料、草稿、审读/
├── 定稿/事务/序号-哈希/
│   └── 事务.json、正文.md、章合同.json、审读.json
└── 导出/正文合集、作者账本、书仓备份.zip
```

目录型事务是本版事实源；不另维护容易不同步的数据库。原始资料与定稿有完整性校验，未知扩展字段保留但不自动赋予约束。

## 三、角色、世界书与知识范围

人物用稳定编号与正名，属性包括动机、关系、状态、位置、能力、口吻等。规则和地点同样有来源。变化使用带时间/段号的属性，避免把后期状态覆盖初期状态。

信息差分别记录“作者知道的事实”“何时向读者披露”“哪些角色何时知道”。语义审读核对对白、行动、内心与获取途径；精确字符串检查只是有限预警。剧情中的谎言和误判作为角色陈述登记，不当真相。

纪实作品使用来源核对与不确定性说明，禁止把虚构提案直接写成真实事件。

## 四、单元规划与期待管理

卷/幕/案是组织单元，章/场/节是全局连续段号。单元卡承载目标、冲突、选择、代价、变化、阶段结局；全书合同管主题与形式，不固定章节规模。

伏笔、悬念、关系期待和主题意象登记为 promise；计划与状态用不同 key，合同明确本段推进。当前 CLI 可登记与查询，不自动算“承诺债”或推断回收成功；真实 GPT 复盘用已确认记录给出到期/未推进报告。后续若需机器计算，再扩展类型专用 schema 与验收。

## 五、创作与审读

备料按 required_fact_ids 选取，按 reveal_at/白名单过滤；不会把全书机密直接喂给起草。正文有明确存储位置，改稿另存。模型实际写作、提取事实并审读，脚本负责完整性与版本边界。

八维审读必须有当前正文原句证据、判断理由及发现项。稿、合同、正史或配置变化导致审读失效。机检能发现占位符、有限显式泄密、篇幅越界及结构问题；不能证明 OOC、因果或文学质量通过。

真实独立审读可在新的 ChatGPT 对话进行，带完整审读包与 fingerprint 回传。第一版同会话分轮工作只实现职责区分，不承诺上下文隔离或完全消除自评偏差。

## 六、定稿、修订与恢复

作者先看到正文和变更，再批准本次入档。引擎写锁保护并发，暂存完整工件后原子重命名为正史。中断前草稿和审读保留；幂等重试不重复入账。

设定修订新来源+新事实ID+supersedes+理由，列出保守影响范围，确认后更新有效视图；历史正文保持原样，不自动续写或改写。

暂停时交付书仓 ZIP；新对话上传最新包后核验并恢复。不能用模型“记得”代替文件，不承诺临时沙盒长期保存。导出正文只含定稿；书仓与看板含作者机密，保持私人。

## 七、部署与隐私

推荐第一版：自定义 GPT Instructions + Knowledge + 数据分析会话上传 ZIP。创建时用户自行选“仅我可见”。没有 GPT Actions、API 服务器、外部数据库或联网运行依赖，因此无需部署与密钥。

ChatGPT 平台的数据处理受用户账号设置与平台条款控制；本包能控制的是不主动对外传输和不公开发布，不能替平台保证零存储或改变账号隐私设置。本次未触碰用户账号可见性，没有 Git 推送、市场发布或对外服务。

可选 Codex 入口使用本地插件源，用户在本地安装；不自动改变全局设置。跨宿主复用 Python 引擎，宿主接口不混用。

## 八、实施与验收状态

| 阶段 | 产物 | 验收 | 当前状态 |
|---|---|---|---|
| 研究 | v6/v8 工作流和版本证据 | 读官方源码与文档 | 已完成 |
| 基础管理 | 来源、候选、合同、账本、备料 | 来源证据、冲突、泄密与越界拦截 | 已实现，本地测试 |
| 闭环 | 审读指纹、八维报告、原子定稿 | 旧稿/旧合同报告不能入档；失败可重试 | 已实现，本地测试 |
| 恢复交付 | ZIP 备份恢复、查询、导出、看板 | 新目录恢复查询一致；定稿不覆盖 | 已实现，本地测试 |
| ChatGPT 接入 | 指令、Knowledge、工具包 | 账号实际创建、运行与下载恢复 | 包已制作，宿主内未验证 |
| 可选 Codex | 插件清单、技能、本地源 | 本地宿主安装 | 格式已核对，未改全局配置 |
| 实际故事 | 作者素材、有效设定、真实审读 | 作者验收 | 等作者选作品/给资料 |

验收不以“脚本输出成功”代替文学质量。测试夹具不是用户故事，不把合成 pass 报告迁入真实作品。

## 九、后续可选扩展

仅在作者确有需要时扩展：本地全文索引、专用承诺状态机、对白说话人解析、历史正文修订包、PDF/EPUB 保真转换、图谱与本地桌面编辑器。远程 Actions、多用户云端持久化、向量 API 需要新的部署和数据边界决定，本次没有启用。

《献生》可配置 `--units 4 --unit-label 案 --segment-label 章 --profile 悬疑推理`，再接入一至四案资料。本方案不声称已知道其主题、凶手、人物设定或现有进度。
